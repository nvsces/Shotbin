# Shotbin

iOS-приложение, которое находит скриншоты в галерее, читает с них текст и раскладывает
по полкам: фильмы из рилсов, коды и пароли, чеки, билеты, адреса, контакты, рецепты.
Напоминает о том, что вы сохранили и забыли. Всё на устройстве — ни один пиксель
не покидает телефон.

## Зачем

Скриншот делают, когда информация нужна: код от домофона, фильм из ленты, бронь столика,
адрес, который скинул друг. Потом он тонет среди тысячи других, и через неделю его уже
не найти. Shotbin возвращает эти скриншоты в момент, когда они снова нужны.

## Что делает

- **Читает текст** — Vision (русский и английский), только скриншоты по `PHAssetMediaSubtype`,
  без перебора всей галереи. Результат кэшируется, повторный запуск мгновенный.
- **Раскладывает по полкам** — правила и словари признаков, без нейросетей и сети:
  Посмотреть · Коды и пароли · Чеки и платежи · Билеты и брони · Адреса и места ·
  Контакты · Ссылки · Переписки · Рецепты · Прочее.
- **Вытаскивает данные с действиями** — код → скопировать, телефон → позвонить,
  адрес → на карте, дата → в календарь, ссылка → открыть, название фильма → найти.
- **Напоминает** — «билет через два дня», «фильм сохранили неделю назад и не отметили»,
  «код лежит месяц — ещё нужен?». За день до даты со скриншота приходит уведомление.
- **Ищет** по любому слову, которое было на экране.
- **Разобрался** — отметить, скрыть или удалить скриншот из галереи прямо из приложения.

## Сборка

```bash
python3 gen_project.py      # пересобрать Shotbin.xcodeproj после добавления файлов
open Shotbin.xcodeproj       # выбрать Team в Signing & Capabilities, ⌘R
```

iOS 17+. Разрешения: Фото (чтение и удаление), Календарь (только запись), Уведомления.

### Проверка в симуляторе

В симуляторе скриншотов нет, поэтому там разбираются все фото. Прогон UI-теста сам
принимает системный диалог доступа к фото, ждёт распознавание, проходит по экранам
и складывает снимки во вложения результата:

```bash
UDID=<id симулятора>
xcrun simctl boot $UDID && xcrun simctl addmedia $UDID samples/*.png   # свои тестовые картинки
xcodebuild test -project Shotbin.xcodeproj -scheme Shotbin -destination "id=$UDID" \
  -resultBundlePath /tmp/shotbin.xcresult
xcrun xcresulttool export attachments --path /tmp/shotbin.xcresult --output-path /tmp/shotbin-shots
```

Аргумент запуска `-autoRequest` заставляет приложение запросить доступ к фото сразу,
без нажатия «Открыть галерею» (нужен только для автотестов).

## Уборка галереи

Скриншот отработал: текст распознан, код скопирован, дата в календаре. Картинка в
галерее больше не нужна, а весит она мегабайты. Экран «Уборка» собирает кандидатов
и удаляет их одной пачкой, оставляя карточку в Shotbin.

Кандидаты подбираются по правилам:

| Группа | Что попадает |
|---|---|
| Разобранные | Отмечены «разобрался» — данные уже в карточке |
| Коды старше месяца | Категория «Коды и пароли», возраст 30+ дней |
| Прошедшие даты | Билеты и брони, у которых дата на скриншоте прошла |
| Без текста | Vision не нашёл текста — разбирать нечего |

После удаления карточка остаётся: сохраняются распознанный текст, находки и
миниатюра в JPEG. В карточке появляется отметка «Место освобождено» с числом
освобождённых байт. Сами картинки система кладёт в «Недавно удалённые» на 30 дней,
так что откат делается через Фото.

## Сканирование

Разбор идёт целиком вне главного потока: Vision, отпечаток кадра и разбор текста
уходят в фоновые задачи, а результаты публикуются пачками по 8 карточек. Каждая
запись в модель пересобирает полки, напоминания и повторы, поэтому публикация
по одному кадру заметно тормозила список.

Скан возобновляемый. Разобранные карточки сохраняются по ходу дела, и в очередь
следующего запуска попадают только те кадры, у которых нет отметки о разборе или
картинка изменилась после него. Кнопка «Пауза» останавливает работу, на главном
экране появляется строка с числом оставшихся кадров и кнопкой «Продолжить».
Прерывание по выходу из приложения работает так же: ничего не теряется, разбор
продолжается с того места, где остановился.

Поиск повторов сравнивает все пары кадров, поэтому результат кэшируется и
пересчитывается только после изменения карточек.

## Конфиденциальность

Приложение не собирает данных: нет сервера, аккаунта, аналитики и сторонних
библиотек. Всё распознавание идёт средствами системы на устройстве.

Страница политики: `docs/index.html`, двуязычная. После включения GitHub Pages
(Settings → Pages → Deploy from a branch → main / docs) она открывается по адресу
`https://nvsces.github.io/Shotbin/` — этот адрес и указывается в App Store Connect.

## Языки

Русский и английский. Строки живут в каталоге `Shotbin/Localizable.xcstrings`,
ключ — русский текст, так что в коде остаются обычные литералы.

Правила разбора текста не переводятся: они с самого начала двуязычные и ищут
и «Итого», и «Total», и «код», и «code». Названия категорий тоже не переводятся
на уровне типа — их значения записаны в сохранённых карточках, и смена
сломала бы кэш у тех, кто уже пользуется приложением. Перевод происходит
на показе, через свойство `title`.

Материалы для App Store и скрипты их сборки лежат в `AppStore/`.

## Фотографии

Скриншоты и обычные фотографии разбираются раздельно.

Основной скан берёт только кадры с системной меткой «снимок экрана» — их и
раскладывает по полкам. Обычные фотографии живут в отдельном разделе, который
пользователь запускает сам. Там не читают текст, а только считают отпечаток кадра
и показывают серии почти одинаковых снимков: несколько кадров одной сцены,
из которых нужен один.

Разделение принципиально: распознавание текста — самая дорогая часть разбора,
и гонять её по снимкам с отдыха незачем. Отпечатку хватает картинки 400 px,
поэтому проверка фотографий идёт заметно быстрее, чем разбор скриншотов.

Порог тот же, 6 ячеек из 256. На проверке настоящие серии дают расстояние 0,
а ближайшие разные снимки — 60, так что запас даже больше, чем у скриншотов.
Кадр «оставить» выбирается по размеру: самый крупный, при равенстве более свежий.

Кэш отпечатков фотографий лежит отдельным файлом `photos.json` и не смешивается
с карточками скриншотов.

## Повторы

Один и тот же экран часто снят несколько раз подряд. Экран «Повторы» собирает такие
серии и предлагает оставить один кадр, а остальные удалить.

Сравнение идёт по отпечатку кадра. Скриншот уменьшается до сетки 16×16 в градациях
серого, каждая ячейка сравнивается со средней яркостью, и получается 256-битный код
раскладки текстовых блоков по странице. Два кадра считаются повтором, если их коды
различаются не больше чем в 6 ячейках из 256 и распознанный текст совпадает.

Обычный dHash на сетке 8×8 здесь не годится: скриншоты — это почти белые страницы,
и такой хэш склеивал в одну серию совершенно разные экраны. На наборе проверки
16×16 даёт расстояние 0–1 между настоящими повторами и 12 до ближайшего чужого кадра.

Кадр «оставить» выбирается автоматически: тот, где больше находок и распознанного
текста, при равенстве — крупнее и свежее. Выбор меняется нажатием на любой кадр
серии, всю серию можно пропустить. Карточки удалённых повторов не сохраняются:
их содержимое дублирует оставшийся кадр.

## Как устроен разбор

`Extractor.swift` — единственное место, где живут правила. На вход строки OCR сверху вниз,
на выход категория, уверенность, находки и однострочная сводка.

1. `NSDataDetector` — даты, телефоны, ссылки, адреса, почта. Даты фильтруются: «12:31»
   и «в пятницу» календарём не считаются, нужен день с месяцем или «завтра».
2. Регулярки — коды подтверждения (в том числе «Код для подтверждения: 482913»),
   Wi-Fi (сеть + пароль), суммы с «Итого», номера заказов, рейсы `SU 1234 MOW→AER`,
   российские телефоны целиком (Apple-детектор режет код страны).
3. Фильмы и книги — маркеры («смотреть», «сериал», «Кинопоиск», «IMDb») плюс строка
   с названием в кавычках или годом в скобках: `«Оппенгеймер» (2023)`.
4. Категория — взвешенная сумма признаков; переписка узнаётся по строкам, оканчивающимся
   временем. Ниже порога — «Прочее». Пользователь может переназначить категорию,
   и это переопределение хранится.

Проверено на синтетических скриншотах семи типов: все семь классифицированы верно.

## Структура

| Файл | Назначение |
|---|---|
| `PhotoLibrary.swift` | доступ к галерее, выборка скриншотов, изображения, удаление |
| `OCR.swift` | Vision, строки в порядке сверху вниз |
| `Extractor.swift` | правила извлечения и классификации |
| `Store.swift` | кэш результатов в JSON |
| `AppModel.swift` | скан, напоминания, действия, уведомления |
| `RootView.swift` | онбординг, главный экран, полки, поиск |
| `DetailView.swift` | скриншот, находки с действиями, смена категории |
